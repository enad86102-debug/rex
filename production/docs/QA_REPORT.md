# تقرير QA والإصلاحات — 2026-10-16

## العيوب والإصلاحات

| العيب | الإثبات والإصلاح |
|---|---|
| مسار مطلق في RexApi يمكنه نقل Bearer إلى أصل آخر | اختبار محلي ببيانات اصطناعية أثبت وصول الطلب؛ رفض المسارات المطلقة وauthority/query/fragment واختلاف origin قبل الإرسال |
| timeout ينهي Future دون إلغاء مصدره | deadline واحدة للاتصال والرؤوس وbody؛ إلغاء stream والطلب المتأخر؛ اختبار socket حقيقي يثبت إغلاق الاتصال المتوقف ثم نجاح طلب تالٍ |
| pending action باقٍ بعد فشل حفظه | اختبار failing vault كشفه؛ فشل الحفظ الأول يمحو النية من الذاكرة، وكل replay يفرض حفظًا قبل الإرسال |
| جلسة ضيف تنشر قبل نجاح التخزين | حفظ الهوية قبل إظهار signedIn؛ محاولة إبطال الجلسة عند فشل التخزين، دون fallback نصي |
| JSON null ينشئ ضيفًا وduplicate/case keys تقبل | فحص flat object صارم، رفض null والحقول المكررة وغير المعروفة وaliases |
| رفض Content-Type صحيح مع charset=utf-8 | استخدام MIME parser وقبول UTF-8؛ اختبار compatibility ناجح |
| DELETE session يترك مالكًا بلا جلسة داخل الغرفة | إزالة مقعد انتظار ونقل ملكية وتدوير دعوة وإبطال جلسة في معاملة واحدة، حتى عند تخطي client لطلب leave |
| snapshot صحيح JSON لكن جلساته معلقة بلا لاعب | تحقق referential integrity والألعاب والإصدارات والملكية والمقاعد والدعوات وبصمات الإيصالات عند Open؛ رفض الحالة الفاسدة |
| تجاهل خطأ إغلاق ملف عند فشل كتابة أو sync | الماسح المتوافق كشف G104؛ تجمع الآن أخطاء الإغلاق والأصل باستخدام errors.Join بدل إسقاط أحدها |
| أداة GLB تنهار مع root array أو تقرأ ملفًا هائلًا | رفض JSON غير object وملف غير عادي أو متجاوز 64 MiB قبل قراءته، مع اختبار regression |
| CI القديم يفشل قبل اختبار فعلي | إصلاح تنسيق واستيراد features_table_scene في test فقط؛ لا استبدال للتطبيق القديم أو تغيير سلوكه |

هذه عيوب كود وعقود مثبتة أو قيود معالجة، وليست ادعاء اكتشاف اختراق لخدمة
إنتاج. رموز إعادة إنتاج الشبكة اصطناعية ومحلية؛ لا بيانات مستخدمين حقيقيين.

## التحقق الحالي

- Go: اختبارات مع race detector وvet وStaticcheck ناجحة؛ مصفوفة 24 طلبًا
  لثمانية مسارات مع جلسة مفقودة أو مزورة أو مبطلة، وتزامن 20 نسخة من أمر
  الإنشاء نفسه للتحقق من تطبيق أثر واحد.
- Go fuzz: 64,271 محاولة خلال نحو 6 ثوانٍ على مدخل JSON، بلا crash. هذه
  مدة مختبر محدودة، لا برهان على غياب أي عيب. الهدف والـseeds في المستودع.
- Flutter production: 11 اختبار unit/widget ناجحًا؛ اختبار live منفصل بأربعة
  transports حقيقية وخادم Go ناجح؛ اختبارا cold process/restart ناجحان.
- Legacy: تحليل و6 اختبارات ناجحة بعد إصلاح test. PBT08: تحليل و6 اختبارات
  ناجحة دون تعديل التجربة. نجاحها لا يحول الواجهات التجريبية إلى gameplay.
- Gitleaks: تاريخ Git المفحوص (13 commit قبل حفظ هذه الدفعة) والـdiff دون
  نتائج أسرار؛ gosec دون نتائج متبقية ودون أخطاء تحليل بعد
  استثناءين G304 مبررين ومحدودين؛ Staticcheck وgovulncheck ناجحان.
  النسخة v2.29.0 من gosec لم تكن فحصًا مكتملًا بسبب تعارض Go export data؛
  استبدلت بـupstream commit مثبت ومتوافق، ثم أصلحت نتيجتي G104 وأعيد الفحص.
- npm audit: لا advisories مكتشفة لتبعية gltf-validator المقفلة؛ 3 اختبارات
  للفاحص الرسمي ناجحة. Python intake: ثلاثة اختبارات ناجحة. اختبارا process
  يشغلان فعليًا عبر check_live؛ يتخطيان صراحة في unittest العام دون binary.
- Khronos: عدد الملفات 19 GLB، errors=0 وwarnings=0. لا skins أو animations
  إنتاجية في الأصول الحالية بحسب intake السابق. **لا اعتماد فني أو حقوق أو
  أداء ضمن هذا النجاح**.
- Android native: ثلاثة اختبارات جديدة للـKeystore والحذف والحجم واستعادة
  جلسة وطاولة مع خادم فعلي؛ أضيف فحص XML مشفر لغياب plaintext marker.
  حالة التنفيذ: ينتظر CI.

## الحدود التي تبقى مانعة للإصدار

لا engines أو عقود قواعد معتمدة أو مباراة نهائية؛ لا اختبار خصوصية أيدٍ
لمحرك غير موجود. لا قياس أجهزة فعلية أو بطارية أو حرارة أو FPS، ولا AAB
موقع أو نشر Play. لا اعتماد بصري للشخصيات والبيئات. محول snapshot ما زال
مرشحًا أحادي العملية وليس قاعدة إنتاج معتمدة.

لا اختبار اختراق مستقل أو شهادة MASVS؛ فحوص backup وphysical-device
وRBAC والتقارير والمراقبة واستعادة الحسابات تبقى أوسع من الدورة الحالية.
لم تشغل MobSF أو ZAP أو k6 أو Trivy، ولا تنسب إليها أي نتيجة.
[سجل قبول الإصدار](RELEASE_ACCEPTANCE.md) يبقى BLOCKED.

## إعادة الفحص والاستكمال

الأوامر في [بحث الأدوات](QA_RESEARCH.md) وworkflow
`.github/workflows/rex-production.yml`. راجع نتيجة android-native الفعلية
قبل إعلان نجاح Keystore. ثم أضف دليل CI والـcommit/PR إلى هذا التقرير.
لا تقبل اتفاقيات SDK محليًا أو تغير القواعد أو تتجاوز المراجعة التقنية باسم QA.
