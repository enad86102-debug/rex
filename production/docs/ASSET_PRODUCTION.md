# حزمة إنتاج الأصول — اعتماد الإصدار محجوب

## ما توفر فعلًا

مراجع الفريق والشعار والأصول القديمة محفوظة كما هي. نسخة الشعار الأصلية فقط
مستخدمة في العميل المنفصل؛ ليست إعادة تصميم. حقوق الاستخدام التجاري وتصدير
launcher النهائي تحتاج مراجعة مالك الأصول. لا صورة مرجعية كاملة مستخدمة
كمشهد تفاعلي، ولا نموذج mannequin مضمن في العميل.

`production/assets/staging-intake.json` يسجل فحص GLB لكل الأصول القديمة.
كل `release_approved` فيه false عمدًا: صلاحية بنية الملف لا تساوي جودة فنية
أو حقوق استخدام. فحص Blender الفعلي لشخصية الشمال القديمة: mesh واحد،
6024 مثلثًا، 0 armatures، 0 actions، 0 UV layers. لا يمكن تحويله إلى إنسان
سينمائي مكتمل بمجرد إعادة تسمية الملف أو إضافة حركة.

## القدرة المفقودة بدقة

Blender 4.3.2 متاح للفحص والتأليف؛ لا توجد في المستودع نماذج بشرية إنتاجية
بمصادر تحرير وrig وskin وحركات وPBR وحقوق مثبتة، ولا مشاهد مستقلة مكتملة
للوجهات الأربع. العائق هو محتوى إنتاج احترافي ومراجعته ودمجه، وليس وجود
برنامج Blender وحده. توليد screenshot لا يسد هذا العائق.

## تسليم كل شخصية إلى فريق الدمج

- مصدر `.blend` قابل للتحرير، textures الأصلية، سجل المؤلف/الحقوق/الرخصة،
  إثبات السماح بالتعديل والتوزيع التجاري داخل لعبة Android.
- بالغون أصليون بتشريح وملابس ووجوه وأيدٍ واقعية دون شبه محمي غير مرخص.
- المتر وحدة قياس، محور up +Y في glTF، root عند أرضية المقعد، export
  transform موثق. اتجاه وجه الشخصية والمحاور المحلية ضمن دليل واحد.
- UV دون أخطاء مرئية، normals/tangents، skin weights مضبوطة، هيكل rig
  موثق وأسماء عظام موحدة. PBR metal/rough مع base color وnormal وORM؛
  فصل المواد ذات الشفافية للحد من overdraw. لا أسماء/ورق متغير داخل textures.
- GLB مستقل، بلا مسارات ملفات خارجية أو node scripts. textures قابلة للضغط
  على Android؛ المصادر تبقى غير فاقدة. تجريب KTX2 بعد اختيار renderer،
  لا فرض extensions غير مدعومة.
- clips مطلوبة: `seated_idle`, `hold_cards`, `play_card`, `reaction_neutral`.
  entrance/victory تنتظر اعتمادًا فنيًا/نطاقيًا؛ لا اختلاق موافقة.
- card socket لكل يد/الموضع المتفق عليه، animation blending موثق، منع
  clipping مع الملابس والطاولة/المقعد. لا تضع أوراق الخصوم داخل mesh.
- LODs وميزانيات مرشحة للمراجعة: 25k/12k/6k triangles للشخصية،
  skeleton <=80 joints، <=4 weights/vertex، atlas 2K/1K، <=3 materials.
  هذه أهداف أولية وليست قياسات أداء أو حدودًا اعتمدها الفريق.

## المقاعد والمشهد

التسميات NORTH/EAST/SOUTH/WEST ثابتة بالنسبة إلى الكاميرا المحلية:
الشمال مقابل الكاميرا، الشرق على اليمين باتجاه الداخل، الجنوب موضع اللاعب
المحلي، الغرب على اليسار باتجاه الداخل. نفس scale وارتفاع المقعد والإضاءة
والكاميرا. يُراجع Blender scene بأربعة مقاعد قبل التصدير، ثم عرض Android
بالمحرك المختار، بما في ذلك رؤية الأيدي وocclusion.

المطلوب أربع بيئات منفصلة: Royal Hall، Wadi Rum، Petra، Aqaba. لا شخصيات
ولا طاولة ولا أسماء أو HUD داخلها. توحيد exposure واتجاه الإضاءة وأفق
الكاميرا. الطاولات/الكراسي Emerald وRoyal Black وSapphire وRuby وIvory
وPurple مستقلة بمواد قابلة للتبديل وسطح ورق مقروء. لا تفعيل كتالوج مدفوع.

## أدوات intake الحالية

```sh
python3 production/tools/inspect_glb.py path/to/character.glb --output intake.json
blender --background --python production/tools/blender_intake.py -- path/to/character.glb
python3 -m unittest discover -s production/tools -p 'test_*.py'
```

الفاحص يقيس skins/joints/animations/UV/normals والتبعيات الخارجية؛ أداة
Blender تفحص الاستيراد وعدد المثلثات والrig وUV. لم يُنفذ validator شامل
لـglTF أو renderer أو blending داخل Flutter؛ كلها أعمال تالية بعد مراجعة
عبدالعزيز لقرار renderer وملفات الشخصيات الفعلية.

## بوابة قبول كل أصل

1. حقوق ومصادر تحرير مكتملة ومراجعة.
2. فحص بنية واستيراد بلا أخطاء، ومراجعة clips وweights/UV يدويًا.
3. مقارنة سينمائية أمام مراجع REX بواسطة الفريق، بما فيها كل المقاعد.
4. قياسات ذاكرة/إطارات/حرارة على أجهزة منخفضة ومتوسطة، والـquality tiers.
5. موافقة الفريق مع reference screenshots فعلية، لا اعتماد آلي.

لا توجد حاليًا شهادة قبول لأي شخصية أو بيئة إنتاجية.
